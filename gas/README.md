# Трекер текущего ремонта — веб-приложение на Google Таблице

Отдельный сайт без Claude, который можно встроить в облачный Битрикс24 (см. ниже). Работает на Google Apps Script, а данные лежат в вашей Google Таблице. Сотрудники входят по имени и PIN-коду, аккаунт Google им не нужен.

## Роли

| Роль | Что может |
|---|---|
| Администратор | Всё: статус, приёмка, исполнитель, перенос месяца, факт ₽, акт, добавление работ, вопросы, пользователи |
| УК | Статус и комментарий только в работах с исполнителем «УК» (своими силами) |
| Подрядчики | Статус и комментарий только в работах с исполнителем «Подрядчики» |
| Просмотр | Только смотрит сводку, список и фото |

Исполнитель закрывает работу статусом «Выполнено, акта нет». Статус «Принято, акт есть» (с номером акта и фактической суммой) и «Снято» ставит только администратор, и вернуть принятую работу исполнитель не может. Это повторяет правило годового плана: жёлтая строка — выполнено без акта, зелёная — принято.

Права проверяет сервер (`Code.gs`), а не страница, поэтому обойти их из браузера нельзя. Работы «Не распределено» отмечает только администратор: он же назначает исполнителя.

## Как читать сводку

Сводка сверху вниз отвечает на три вопроса: на какой стадии работы, где проблемы и кто отстаёт.

1. **Где мы сейчас** — процент выполненных работ и шесть стадий. Четыре идут по ходу работы, две стоят вне его (пунктиром). Под числом стадии — сколько в ней проблемных: «месяц плана прошёл», «дольше плана», «акт задерживается», «просрочено».
2. **Где проблемы** — восемь проверок по важности, у каждой указано, кто решает. Красное срывает сроки, жёлтое копится, серое — порядок в данных.
3. **По месяцам плана** — состояние каждого месяца: «просрочен» (месяц закончился, работы не сделаны), «без акта N» (всё сделано, не все акты оформлены), «закрыт», «идёт сейчас», «впереди».
4. **Кто отстаёт** — исполнители, мастера участков или управляющие компании. Первыми идут те, у кого больше просроченных работ.
5. **Адреса с проблемами** и **Просрочено по видам работ**.

Любая карточка, строка или столбик открывает список этих работ с уже выставленными отборами. Работа просрочена, если месяц плана закончился, а она не начата, в работе или стоит.

| Стадия | Статусы |
|---|---|
| Не начато | Не начато, Передано исполнителю |
| В работе | В работе, На контроле, Материал заказан |
| Выполнено, ждёт акта | Выполнено, акта нет |
| Принято с актом | Принято, акт есть |
| Отложено на зиму | Отложено на зиму |
| Нужно решение | Нужно решение, Требует уточнения, Нет статуса, Вопрос капремонта, Голосование ОСС |
| Снято с плана | Снято — в проценты не входит |

Те же стадии и проверки — на листе «Сводка» в Excel-файле сводного трекера (`reports/`).

## Страница по капитальному ремонту

Отдельная страница-сводка по перечню работ капитального ремонта (файл `.xls` с колонками «Решение собственников», «Сумма КР», «Основной подрядчик», «Срок окончания», «процент выполнения» и др.), оформленная так же, как «Текущий ремонт». Входа не нужно, это один HTML-файл.

```
python3 tools/build_kr.py <перечень .xls> --today 2026-10-27
```

Результат: `reports/Капитальный ремонт <дата>.html` (для рассылки) и `capital/kr.html` (для публикации). Колонки ищутся по заголовкам, поэтому порядок колонок не важен. Этапы определяются по проценту выполнения (в файле нет статуса): «процент не указан», «в работе» (1–99%), «выполнено» (100%), «встали». Страница показывает проблемы (срок прошёл, отставание от графика, нет договора, нет срока, нет исполнителя и др.), деньги, сроки окончания, подрядчиков и список позиций с деталями; внизу — вопросы к файлу.

## Фото «до» и «после»

В карточке работы есть блок **Фото** с двумя колонками. Кнопка «+» добавляет снимки (с телефона можно сразу снять камерой), нажатие на миниатюру открывает снимок крупно, там же «Скачать» и «Удалить».

- **Кто что может.** Смотреть может любой вошедший. Добавляют те, кто может править эту работу: администратор, «УК» в своих работах, «Подрядчики» в своих. Удаляет администратор или тот, кто добавил фото.
- **Где хранится.** Снимки лежат на Google Диске владельца трекера, в папке «Трекер текущего ремонта — фото» (создаётся сама, посторонним она недоступна). Лист «Фото» в таблице помнит, какой снимок к какой работе относится, кто и когда его добавил; в нём же маленькие миниатюры.
- **Что с размером.** Браузер сжимает каждый снимок до 1600 px по длинной стороне (обычно 150–500 КБ), поэтому с телефона грузится быстро. Данные о съёмке, в том числе геометки, при этом не сохраняются. Принимаются JPEG, PNG и другие обычные форматы; снимки HEIC с iPhone нужно сохранить как JPEG. К одной работе — до 20 фото «до» и до 20 «после».
- **Контроль.** В списке работ у работы с фото видно «фото: до N, после M». В дополнительном отборе есть «Выполнено, а фото «после» нет». В выгрузке Excel для каждой работы есть число фото.

**Один раз при подключении:** в редакторе скриптов выберите функцию `authorizePhotos`, нажмите «Выполнить» и разрешите доступ к Google Диску, затем разверните новую версию веб-приложения. Без этого при добавлении первого фото трекер подскажет то же самое.

## Выгрузка в Excel

Кнопка **Скачать Excel** есть на «Сводке» и в «Работах». В файле два листа: «Сводка» (те же цифры, что на странице: стадии, проблемы, месяцы, исполнители, мастера, управляющие компании) и «Работы» (все колонки, включая стадию, просрочку, акт, мастера, Битрикс24 и число фото; включён фильтр). С «Работ» выгружается ровно тот список, который вы сейчас видите с отборами; со «Сводки» — все работы. Роль «УК» или «Подрядчики» при выборе «Мои» получает только свои работы. Библиотека для файла подгружается из интернета при первой выгрузке.

## Установка (около 10 минут)

1. Создайте новую Google Таблицу, например «Трекер текущего ремонта».
2. Откройте **Расширения → Apps Script**.
3. В редакторе:
   - замените содержимое `Code.gs` на файл `Code.gs` отсюда;
   - **+ → Скрипт**, назовите `Seed`, вставьте содержимое `Seed.gs`;
   - **+ → HTML**, назовите `Index`, вставьте содержимое `Index.html`;
   - **Настройки проекта (шестерёнка) → Показывать файл манифеста appsscript.json**, затем замените его содержимое на `appsscript.json`.
4. Выберите в списке функцию `setup` и нажмите **Выполнить**. Google попросит разрешение на доступ к таблице, дайте его.
   В **Журнале выполнения** появится строка `Администратор создан. Имя: «Администратор», PIN: ……`. Запишите PIN.
   В таблице появятся листы «Работы», «Пользователи», «Журнал», «Вопросы». Лист «Фото» появится при первом снимке.
5. **Начать развёртывание → Новое развёртывание → Тип: Веб-приложение**:
   - «Запуск от имени»: **Я**;
   - «У кого есть доступ»: **Все**.
   Нажмите «Начать развёртывание» и скопируйте ссылку вида `https://script.google.com/macros/s/…/exec`. Это адрес трекера.
6. Откройте ссылку, войдите как «Администратор» и на вкладке **Пользователи** заведите сотрудников, например Филимонова с ролью УК и сотрудника ПТО с ролью Подрядчики, и задайте каждому PIN.

Саму таблицу никому не открывайте: сотрудники работают только через ссылку. Таблица остаётся у вас и служит базой данных и резервной копией.

## Как это работает

- **Работы** — по строке на работу. Отметки из трекера пишутся в колонки «Статус», «Исполнитель», «Комментарий», «Изменено», «Кем». Администратор может править таблицу и напрямую: трекер подхватит изменения.
- Дополнять план можно и прямо в таблице: вставьте строку с месяцем (`2026-11`), адресом и работой без ключа — при следующем открытии трекера ключ появится сам.
- При переносе работы на другой месяц исходный месяц сохраняется в колонке «Исходный месяц», а в трекере видно «перенесено из сентября».
- **Журнал** — кто, когда и что поменял.
- **Пользователи** — PIN хранится хэшем. Чтобы быстро сменить PIN прямо в таблице, впишите новый в колонку «Новый PIN»: при первом входе он превратится в хэш и сотрётся.
- После 5 неверных PIN подряд вход под этим именем блокируется на 15 минут. Сессия длится 6 часов.
- Открытые страницы раз в 45 секунд проверяют изменения и обновляются сами.

## Встраивание в Битрикс24 (облачный)

Трекер открывается внутри портала пунктом левого меню. Сотрудник входит под своей учётной записью Битрикс24, без PIN. Подрядчики без Битрикса по-прежнему входят по прямой ссылке и PIN.

1. Сначала выполните установку выше и разверните **новую версию** веб-приложения: в ней есть вход из Битрикса.
2. В редакторе Apps Script: **Настройки проекта → Свойства скрипта → Добавить свойство**:
   - свойство `BITRIX_DOMAIN`;
   - значение — адрес портала без `https://`, например `uk-sv.bitrix24.ru`.
3. В Битрикс24 (нужны права администратора портала): **Приложения → Разработчикам → Другое → Локальное приложение**:
   - тип: **Серверное**;
   - «Использует только API»: **выключено**;
   - «Путь вашего обработчика»: ссылка на трекер `https://script.google.com/macros/s/…/exec`;
   - «Путь для первоначальной установки»: та же ссылка;
   - «Название пункта меню»: «Текущий ремонт»;
   - права: **Пользователи (user)**.
   Сохраните. Пункт «Текущий ремонт» появится в разделе «Приложения», его можно перетащить в левое меню.
4. Каждый сотрудник один раз открывает «Текущий ремонт» и попадает в трекер с ролью «Просмотр». Администратор на вкладке **Пользователи** назначает роль, например Ивану Филимонову — «УК».
   Можно сделать это заранее: создать пользователя и вписать **ID в Битрикс24** — число из адреса профиля `…/company/personal/user/15/`.

Как защищён вход: трекер проверяет сотрудника запросом `user.current` к порталу из `BITRIX_DOMAIN`, а не к тому адресу, который пришёл в запросе. Поэтому чужой портал или подделанный ключ войти не даст. Отключённый в трекере сотрудник не войдёт и из Битрикса.

Если сотрудник видит «Битрикс24 не подтвердил вход», пусть закроет приложение и откроет снова: ключ Битрикса живёт около часа.

## Обновление кода

После правок в `Index.html` или `Code.gs`: **Начать развёртывание → Управление развёртываниями → карандаш → Версия: новая → Развернуть**. Ссылка не меняется.

## Файлы

- `Code.gs` — сервер: вход, права, чтение и запись таблицы.
- `Index.html` — интерфейс: сводка, работы, вопросы, журнал, пользователи.
- `Seed.gs` — сводный план на 20.10.2026 (443 работы, 29 вопросов), загружается функцией `setup()`.
- `demo.html` — та же страница с данными внутри, открывается в браузере без сервера. Вместо PIN выбирается роль, изменения не сохраняются.
- `meeting.html` — демо-страница для показа на claude.ai, телефоны жильцов скрыты.
- `merge.js` — сведение выгрузок Excel в браузере (порт `tools/merge_sources.py`); `build.py` вставляет его в `Index.html`, править нужно `merge.js`.
- `build.py` — пересобирает `Seed.gs`, `demo.html`, `meeting.html`, страницу для скачивания `reports/Трекер текущего ремонта <дата>.html` и файл обновления `reports/Обновление для трекера <дата>.json` из `../tracker/merged.json` и `../tracker/questions.json`.

## Обновление данных в работающем трекере

Когда пришли новые выгрузки, данные в работающую таблицу загружаются кнопкой, а не повторным `setup()`. Трекер сам читает файлы Excel, ничего конвертировать не нужно:

1. Администратор открывает **Работы → Загрузить обновление**, вкладка **Из файлов Excel**.
2. Выбирает три файла: годовой план ПТО (`.xls` или `.xlsx`), файл исполнителей, выгрузку Битрикс24. Даты выгрузок подставятся сами (дату файла исполнителей берёт из названия листа «Тек.Рем (дата)»), при необходимости их можно поправить: при расхождении источников побеждает более свежий.
3. Нажимает **Свести и показать, что изменится**. Сведение идёт в браузере, файлы никуда не отправляются. Трекер покажет, что прочитано и что изменится.
4. Ничего не записывается, пока не нажата кнопка **Применить**.

Для работы нужен интернет: при первом открытии окна браузер подгружает библиотеку чтения Excel (SheetJS 0.18.5 с jsDelivr, запасной адрес — cdnjs). Если сеть закрыта, используйте вкладку **Готовый файл .json**: файл `reports/Обновление для трекера <дата>.json` собирают командами из раздела ниже.

Как читаются файлы:

- В годовом плане берётся лист с названием года («2026»); цвет строки (зелёная — принято, жёлтая — выполнено без акта, красная — снято, оранжевая — УК, серая — подрядчики) читается из самого файла. Если цвета не прочитались, трекер предупредит.
- В файле исполнителей листы находятся по началу названия: «Тек.Рем…» (основной), «пополнение…» (пополнения), остальные — листы мастеров.
- В выгрузке Битрикс24 читается первый лист.
- Нужны все три файла: без любого из них трекер не сможет отличить новую работу от пропавшей.

Что делает загрузка:

| Ситуация | Что происходит |
|---|---|
| Работа есть в файле и в таблице | Обновляются стадия и сроки Битрикс24, номер строки плана, источники статуса |
| Работу никто не менял в трекере | Статус, исполнитель, мастер, акт, факт, оценка и месяц берутся из файла, но статус только вперёд, назад не откатывается |
| Работу менял сотрудник | Его статус, комментарий, исполнитель, мастер, акт, факт и месяц остаются. Пустые поля (мастер, акт, факт) заполняются. Если источники ушли дальше его отметки, работа получает метку «сверить» |
| Работы нет в таблице | Добавляется |
| Работы нет в файле | Остаётся без изменений, не удаляется |
| Месяц работы в плане изменился | Работа находится по адресу и тексту; месяц меняется, если её не трогали в трекере |
| Тот же файл загружен повторно | Ничего не меняется |

Каждое изменение записывается в «Журнал» с пометкой «Импорт». Загружать может только администратор, файл проверяется на формат и ограничен по размеру.

## Обновление данных из выгрузок

Когда приходят новые файлы (годовой план ПТО, файл исполнителей, выгрузка Битрикс24):

```
python3 tools/merge_sources.py <годовой план .xls> <файл исполнителей .xlsx> <выгрузка Битрикс24 .xlsx> \
    --plan-date 2026-10-26 --exec-date 2026-10-08 --bx-date 2026-10-27 --today 2026-10-27
python3 tools/questions.py      # перечень вопросов
python3 tools/make_reports.py   # reports/: сводный трекер и вопросы в Excel
python3 gas/build.py            # Seed.gs, demo.html, страницы для показа и скачивания, reports/Обновление для трекера <дата>.json
```

Даты — это числа, на которые актуальны выгрузки (если не указаны, берётся дата файла, а у файла исполнителей — дата из названия листа «Тек.Рем (дата)»). От них зависит, какой источник считается свежее при расхождении, и подписи в примечаниях работ. Листы в файле исполнителей находятся по началу названия, поэтому после смены даты в названии ничего менять не нужно.

После правок `merge.js` или `tools/merge_sources.py` запустите `node tools/test_merge_js.js <план> <исполнители> <Битрикс24>`: он сравнивает результат браузерного сведения с Python и должен показать 0 расхождений.

Сведение сопоставляет работы по адресу и тексту работы. Статус берётся из самого свежего источника. Устаревшая стадия Битрикс24 не отменяет отметку «выполнено» от ПТО или исполнителя: такие работы помечаются «Сверить». Всё, что не сошлось, записывается в `tracker/merge_report.json` и в лист «Сверка».
