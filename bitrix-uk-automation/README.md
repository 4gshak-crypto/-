# bitrix-uk-automation

Программа наполняет и ведёт смарт-процесс «Дома» в облачном Битрикс24 (портал ul-73.ru, entityTypeId 1092, ID типа 13) для УК СВ, УК СОЮЗ и ДОМОВОЙ (около 250 МКД). Данные берутся из выгрузок: у АСУ «Жилищный стандарт» API нет.

| Команда | Что делает | Готова |
|---|---|---|
| `check` | проверяет подключение, права вебхука (crm, task, user), смарт-процесс 1092, ответственного Шакирова | да |
| `discover` | читает поля, стадии и сотрудников, предлагает сопоставление «колонка CSV → поле», пишет `config/fields_map.yaml` | да |
| `asu-preview` | разбор журнала АСУ **без Битрикса**: аварии, третьи стороны, «не выполнено», повторы, проверка адресов по реестру домов | да |
| `import-houses` | upsert домов из `input/дома_для_импорта.csv` | шаг 3 |
| `sync-asu-journal` | дела и задачи по заявкам АСУ из `input/asu/*.xlsx` | шаг 4 |
| `report` | сводка в Excel и markdown | шаг 4 |

Концепция продукта, модель данных и дорожная карта — в [docs/concept.md](docs/concept.md).

## Установка

Нужен Python 3.11 или новее.

```bash
cd bitrix-uk-automation
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'      # в Windows: .venv\Scripts\pip install -e .[dev]
cp .env.example .env                   # и впишите адрес вебхука
```

Запуск: `.venv/bin/python -m bitrix_uk <команда>` или короче `.venv/bin/bitrix-uk <команда>`.

## Как создать входящий вебхук

Нужны права администратора портала.

1. Битрикс24 → **Приложения** → **Разработчикам** → вкладка **Другое** → **Входящий вебхук**.
2. В «Настройке прав» отметьте **CRM (crm)**, **Задачи (task)**, **Пользователи (user)**. Больше ничего не нужно.
3. Нажмите **Сохранить** и скопируйте адрес вида `https://ul-73.ru/rest/<номер>/<ключ>/`.
4. Впишите его в `.env`:
   ```
   BITRIX_WEBHOOK_URL=https://ul-73.ru/rest/<номер>/<ключ>/
   ```
   Вместо `.env` можно задать переменную окружения `BITRIX_WEBHOOK_URL`: она важнее файла.

Вебхук работает с правами пользователя, который его создал. Программа видит и меняет только то, что доступно этому сотруднику. Адрес вебхука — это пароль: не пересылайте его в чатах и почте. Если он утёк, удалите вебхук в Битриксе и создайте новый.

## Порядок работы

```bash
bitrix-uk check                       # 1. подключение и права
bitrix-uk discover                    # 2. поля и стадии → config/fields_map.yaml
#    откройте config/fields_map.yaml, проверьте раздел mapping, поставьте confirmed: true
bitrix-uk import-houses               # 3. показать, что будет создано и изменено (ничего не пишет)
bitrix-uk import-houses --apply       # 4. записать, после ввода «да»
```

### Что показывает discover

- Таблицу полей смарт-процесса: код для API (`ufCrm13...`), код `UF_CRM_13_...`, подпись, тип.
- Стадии всех воронок с `STATUS_ID`.
- Предложение «колонка CSV → поле». Оно строится **только по совпадению подписей**:
  - `точно` — подпись совпала (регистр, «ё», «м²/м2» и знаки препинания не важны);
  - `похоже` — подпись почти совпала, проверьте;
  - `нет` — подходящего поля нет. Впишите `field` сами (код из раздела `fields`) или оставьте пустым, тогда колонка не загружается;
  - если подходят несколько полей, программа ничего не выбирает и перечисляет их в примечании.
- Список сотрудников в `config/users.yaml`. Он нужен для сопоставления техников и в git не попадает.

Если `fields_map.yaml` уже подтверждён (`confirmed: true`), повторный discover его не перезаписывает и сохраняет результат рядом, в `fields_map.discovered.yaml`.

## Разбор журнала АСУ без Битрикса

```bash
bitrix-uk asu-preview                          # все выгрузки из input/asu
bitrix-uk asu-preview input/asu/ADocumentJournal_appealss-07-10-2026.xlsx --limit 100
```

Вебхук не нужен, в Битрикс ничего не отправляется. Команда показывает:
- **аварии** и сработавшее правило (затопление, порыв, колодцы и КНС, лифт…);
- **заявки «Третья сторона»**: кому передано (по тексту комментария) и время передачи из отметки комментария;
- **заявки, по которым жилец ответил «Не выполнено»**;
- **повторяющиеся проблемы**: 3 и больше заявок по одной системе дома за 30 дней;
- **адреса, которые не нашлись в реестре** или подходят к нескольким домам, если в `input/` лежит `дома_для_импорта.csv`.

Правила (ключевые слова аварий, системы, третьи стороны) лежат в `config/asu_rules.yaml`, их можно дополнять без правки кода. Решения по спорным адресам записываются в `config/address_aliases.yaml`.

ФИО заявителей программа не читает. Телефоны, e-mail и ФИО с инициалами в тексте заявок маскируются. Ограничение: фамилию без инициалов («позвонить Иванову») маска не распознаёт.

## Безопасность

- Вебхук хранится только в `.env` или в переменной окружения. В код, журналы и тексты ошибок он не попадает: журнал дополнительно вырезает всё похожее на `/rest/<номер>/<ключ>`. `.env` в `.gitignore`.
- По умолчанию все команды только показывают изменения. Запись начинается только с `--apply` и после ввода «да».
- Программа вызывает только методы из белого списка (`client.py`). Методов удаления в нём нет, любой метод со словом `delete` блокируется ещё до отправки. Методы записи заблокированы, пока клиент не создан для `--apply`.
- Стадии и задачи автоматически не меняются и не закрываются.
- Не больше 2 запросов в секунду. При `QUERY_LIMIT_EXCEEDED`, ошибках 5xx, таймаутах и обрывах связи запрос повторяется с паузами 1, 2, 4, 8, 16 с.
- Программа ничего не отправляет жителям и внешним организациям, только пишет в Битрикс24.
- ФИО и телефоны заявителей в журнал не пишутся.

## Файлы

```
config/settings.yaml      портал, entityTypeId, лимиты, ответственный за задачи третьим сторонам
config/fields_map.yaml    результат discover + ваше подтверждение
input/                    дома_для_импорта.csv; input/asu/ — выгрузки ADocumentJournal_*.xlsx
output/logs/app.log       журнал (INFO); errors.log — только ошибки
output/reports/           отчёты
src/bitrix_uk/            client.py, config.py, discover.py, cli.py, matching.py (адреса), asu.py (журнал АСУ), houses.py (реестр домов)
tests/                    тесты на вымышленных данных: .venv/bin/pytest
```

Содержимое `input/`, `output/`, `state.db` и `config/users.yaml` в git не попадает.
