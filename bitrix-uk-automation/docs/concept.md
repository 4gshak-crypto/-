# «Паспорт МКД» для Битрикс24 — концепция продукта

Рабочее название. Документ описывает, что строим, как устроены данные и как продукт потом продавать другим управляющим компаниям. Это основа для кода: схема данных отсюда переносится в `config/schema.yaml`, по ней программа проверяет и настраивает портал.

Версия 1.1, 20.10.2026: добавлены обращения ГИС ЖКХ по выгрузке от 07.10.2026. Пункты, которые требуют вашего решения, помечены **[решить]**.

## 1. Суть

**Карточка дома — единственное место, где видна вся жизнь дома.** Открыл «ул. Аблукова, 11» и видишь паспорт дома, все работы за все годы с актами и суммами, все заявки и аварии, оборудование со сроками поверки, осмотры, предписания ГЖИ, документы. Видно и кто, когда и на каком основании это делал.

**Данные не вводятся вручную, если они уже где-то есть.** Дома берутся из выгрузки ГИС ЖКХ и АСУ, заявки из журнала АСУ, план работ из годового плана текущего ремонта. Программа загружает их повторяемо и без дублей. Люди только подтверждают работы, прикладывают акты и фото и закрывают вопросы.

**Продукт живёт внутри Битрикс24 клиента.** У большинства УК Битрикс уже есть, новую систему внедрять не нужно, данные остаются у клиента. Мы поставляем схему, загрузчики, отчёты и методику.

## 2. Какие проблемы решаем

| Проблема сегодня | Что даёт продукт |
|---|---|
| История дома разбросана по Excel-планам, АСУ, бумажным актам и памяти техников. Ушёл техник — ушла история | Вся история в карточке дома, привязана к дому, а не к человеку |
| Житель или совет дома говорит «ничего не делали». Найти доказательства — день работы | По дому за минуту: список работ с актами, фото «до/после», суммами |
| Отчёт собственникам за год собирается вручную по каждому дому | Отчёт по дому формируется из истории работ (ч. 11 ст. 162 ЖК РФ — ежегодно, в первом квартале) |
| Повторная авария там, где подрядчик недавно делал ремонт, и никто не вспомнил о гарантии | Программа видит повтор по той же системе дома и действующую гарантию и ставит задачу на претензию |
| Сроки предписаний ГЖИ, поверок ОДПУ, освидетельствований лифтов держатся в голове | Сроки — поля с напоминаниями. Просрочка видна заранее |
| Заявки «третьей стороне» (Водоканал, Т+, провайдеры, лифтовые) теряются | По каждой автоматически ставится задача ответственному с контролем |
| Нельзя сравнить дома, техников, подрядчиков | Показатели: аварийность, затраты на м², доля работ с актами, исполнение плана |

## 3. Принципы

1. **Дом — центр.** Любая запись (работа, заявка, осмотр, предписание, оборудование) обязательно привязана к дому.
2. **У каждой записи есть основание и подтверждение.** Основание — заявка, протокол ОСС, предписание, осмотр или план. Подтверждение — акт, фото, дата приёмки. Работа без акта не считается принятой. Это правило уже работает в вашем трекере: жёлтая строка — выполнено без акта, зелёная — принято.
3. **Ничего не удаляется.** Ошибочную запись переводят в финальную стадию «Снято» или «Дубль». История изменений полей ведётся Битриксом автоматически.
4. **У каждой загруженной записи есть ключ источника.** Например `ASU-123456` или `PLAN-2026-159`. Повторная загрузка обновляет запись, а не создаёт копию. Ключ хранится в самой записи Битрикса, поэтому даже потеря локальной базы программы не приведёт к дублям.
5. **Минимум персональных данных.** ФИО и телефоны жителей из АСУ в Битрикс по умолчанию не переносятся. Номер помещения переносится, он нужен, чтобы видеть повторы. Телефоны, которые жители пишут в тексте заявки, маскируются.
6. **Ничего не зашито под одну УК.** Портал, юрлица, справочники, форматы выгрузок задаются в настройках. Это условие, без которого продукт нельзя продавать другим.

Работа всегда привязана к дому. Дополнительно её можно привязать к тому, из-за чего она появилась: к заявке, осмотру, обращению, предписанию или оборудованию. Битрикс24 позволяет связать смарт-процесс с несколькими «родителями». Тогда, например, в карточке предписания будет вкладка «Работы», а в карточке лифта — его ремонты.

| Сущность | Где живёт | Что это | Этап |
|---|---|---|---|
| Дом | смарт-процесс 1092 (уже есть) | паспорт дома | MVP |
| Работы | новый смарт-процесс | вся ремонтная история | MVP |
| Заявки и аварии | новый смарт-процесс | копия журнала АСУ для истории и контроля | MVP |
| Оборудование | новый смарт-процесс | лифты, ИТП, ОДПУ, насосы, ВРУ, АППЗ | 2 |
| Осмотры | новый смарт-процесс | сезонные и внеочередные осмотры, готовность к ОЗП | 2 |
| Обращения и предписания | новый смарт-процесс | переписка по дому с РСО, администрацией, ГЖИ (из ГИС ЖКХ); предписания и проверки | MVP — обращения ГИС ЖКХ; 2 — предписания |
| Подрядчики, РСО | стандартные «Компании» CRM | кто делает и кому передаём | MVP |
| Председатели советов домов | стандартные «Контакты» CRM | контакт дома | 2 |
| Задачи | стандартные задачи с привязкой к дому или работе | контроль исполнения | MVP |
| Документы дома | поле «Файлы» и папка дома на Диске | техпаспорт, протоколы ОСС, договоры | MVP |

**[решить]** Для новых смарт-процессов нужно право на настройку CRM, обычно оно есть у администратора портала. Проверьте и лимит вашего тарифа Битрикс24 на число смарт-процессов: всего их будет 6, вместе с «Домами»; в MVP — 4: Дома, Работы, Заявки, Обращения.

### 4.2. Дом (существующий смарт-процесс 1092)

Поля сгруппированы так, как их удобно показать в карточке. Состав подтвердится после `discover`: недостающие поля программа предложит добавить.

| Группа | Поля |
|---|---|
| Идентификация | Название («ул. Аблукова, 11»), короткий адрес, адрес ОЖФ, **GUID дома ГИС ЖКХ (главный ключ)**, ФИАС GUID, код ОКТМО, кадастровый номер |
| Управление | УК (юрлицо), наименование УО в ГИС, ОГРН УО, способ управления, договор управления № и дата, дата начала управления, техник/мастер участка (= «Ответственный»), председатель совета (контакт), тариф содержания ₽/м² |
| Характеристики | тип дома, состояние дома (по ГИС), год постройки, этажность, подъездов, помещений (ГИС), из них нежилых, квартир (АСУ), общая и жилая площадь, конструктив, тип кровли |
| Инженерные системы | отопление, ГВС, газ, лифтов (шт.), ОДПУ тепла, воды, электроэнергии, АПС |
| Капремонт | программа ФКР: виды работ и годы |
| Качество данных | найден в АСУ, требует проверки, расхождения (текст, заполняет программа: например, «площадь ГИС 3 120 м², АСУ 3 054 м²») |
| **Показатели** (считает программа) | заявок за 12 мес., аварий за 12 мес., повторных аварий, затраты на ремонт в этом году и за всё время, ₽ и ₽/м², работ в плане и просрочено, работ без акта, открытых предписаний, последний осмотр, действующих гарантий, дата пересчёта |
| Документы | техпаспорт, протоколы ОСС, акты, ссылка на папку дома на Диске |

**Стадии дома:** Приёмка в управление → В управлении → Расторжение договора → Вышел из управления (финал).

**[решить] Стадия «Аварийное состояние».** Предлагаю её переименовать. В жилищном праве «аварийный дом» означает дом, признанный аварийным и подлежащим сносу или реконструкции. Это постоянный статус, и он уже есть в колонке CSV «Состояние дома». Если назвать так стадию, которая включается на время аварии, их перепутают, в том числе при проверке. Варианты:
- (а) стадия «Авария: идёт устранение». После устранения программа сама предложит вернуть дом в «В управлении»;
- (б) рекомендую: вместо стадии поле-флаг «Открытая авария» со ссылкой на заявку. Тогда стадия всегда показывает статус управления, а аварийные дома видны фильтром.

### 4.3. Работы — ядро истории

Сюда попадает каждая работа по дому: из годового плана текущего ремонта, из аварийной заявки, по итогам осмотра, по предписанию, по решению ОСС, по капремонту ФКР.

| Поле | Зачем |
|---|---|
| Название | что сделать или что сделано: «Ремонт кровли над кв. 45, 30 м²» |
| Дом (обязательно); оборудование, заявка, осмотр, предписание (если есть) | связи |
| Вид работ | содержание и ТО / текущий ремонт / аварийно-восстановительные / по решению ОСС / капремонт ФКР / гарантийные |
| Конструктив или система | справочник (раздел 6): кровля, фасад, ХВС, ЦО… Даёт историю по системе: «все работы по кровле этого дома» |
| Место | подъезд, этаж, квартира, участок |
| Основание | тип (план, заявление, заявка АСУ, протокол ОСС, предписание, акт осмотра, ГИС ЖКХ) + номер и дата |
| Исполнитель | свои / подрядчик + компания-подрядчик |
| План | плановый месяц, плановая дата, исходный месяц (если работу переносили) |
| Факт | дата выполнения, дата приёмки, объём и единица измерения |
| Деньги | сметная сумма, фактическая сумма, источник финансирования (содержание и ремонт / текущий ремонт / ФКР / целевой сбор по ОСС / за счёт подрядчика по гарантии) |
| Подтверждение | акт № и дата, файл акта, смета, фото «до» и «после» |
| Гарантия | гарантия до (дата); флаг «гарантийный случай» и ссылка на исходную работу |
| Ключ источника | `PLAN-2026-159`, `ASU-123456`, `MANUAL` — защита от дублей |

**Стадии.** Перенесены из вашего трекера, чтобы привычная логика не менялась:

| Стадия Битрикса | Статусы трекера, которые в неё попадают |
|---|---|
| Нужно решение | Нужно решение, Требует уточнения, Нет статуса, Вопрос капремонта |
| Голосование ОСС | Голосование ОСС |
| Запланировано | Не начато |
| Передано исполнителю | Передано исполнителю, На контроле |
| Материал заказан | Материал заказан |
| В работе | В работе |
| Отложено на зиму | Отложено на зиму |
| Выполнено, акта нет | Выполнено, акта нет |
| **Принято, акт есть** (финал, успех) | Принято, акт есть |
| **Снято** (финал) | Снято |

Правила:
- в стадию «Принято» нельзя перевести без акта, даты приёмки и фактической суммы (в Битриксе это настраивается как «обязательно на стадии»);
- «Принято» и «Снято» ставит только ПТО или руководитель (права роли);
- при приёмке в ленту дома пишется событие: «Принята работа: …, акт №…, … ₽».

### 4.4. Заявки и аварии (копия журнала АСУ)

АСУ остаётся главной системой для заявок. Битрикс хранит копию: для истории дома, для контроля третьих сторон и для показателей.

| Поле | Примечание |
|---|---|
| № заявки АСУ | ключ, по нему повторная загрузка обновляет статус |
| Дом, помещение | дом определяется по нормализованному адресу; неоднозначные адреса программа не выбирает сама, а выводит на проверку |
| Время создания (АСУ), время передачи | время передачи берётся из комментария, потому что время АСУ бывает смещено на час |
| Содержание | телефоны в тексте маскируются |
| Тип, источник, исполнитель, статус АСУ, комментарий | как в АСУ |
| Система | определяет программа по ключевым словам; справочник тот же, что у работ |
| Критичность | авария / срочная / плановая. Аварии: затопление, порыв, пожарная сигнализация, запах гари, нет отопления в доме, лифт, колодцы и КНС |
| Третья сторона | Водоканал / Т+ / провайдер / лифтовая / другое |
| Повторная | да, если в этом доме по той же системе была заявка за последние N дней; ссылка на предыдущую |

**Стадии:** Новая → В работе → У третьей стороны → Выполнена (финал) / Отклонена или дубль (финал).

**Что программа делает сама после загрузки.** Всё ниже — в режиме предпросмотра, запись только после `--apply` и подтверждения:
- **авария** — событие в ленте дома; если по этой системе есть работа с действующей гарантией, задача «Проверить гарантийный случай»;
- **«Третья сторона» с пустым комментарием** — задача Шакирову с привязкой к дому и заявке;
- **авария, которая требует ремонта**, — предложение создать работу со ссылкой на заявку.

**[решить]** Загружать в Битрикс все заявки или только значимые (аварии, третьи стороны, повторные)? Рекомендую все: на них держатся история и показатели. Сколько заявок в месяц у вас обычно бывает? Это нужно для расчёта времени загрузки.

### 4.5. Оборудование (этап 2)

Лифты, ИТП, ОДПУ тепла, ХВС, ГВС и электроэнергии, насосы, ВРУ, АППЗ и дымоудаление, ВДГО, домофоны, видеонаблюдение, вентиляция.

**Поля:** вид, место установки, производитель, модель, заводской и инвентарный номер, год ввода, нормативный срок службы, обслуживающая организация (компания), договор, периодичность ТО, последнее и следующее ТО, последняя и следующая поверка или освидетельствование, страховка ОСОПО до (для лифтов), признак «жизнеобеспечение», паспорт и протоколы.

**Стадии:** Исправно → Требует ремонта → Не работает → Списано (финал).

**Стартовое наполнение.** В CSV домов уже есть «Лифтов, шт.», «ОДПУ тепла/воды/э/э», «АПС». Программа создаст по ним карточки-заготовки («Лифт №1», «ОДПУ тепла») с пометкой «заполнить паспорт». Так сразу видно, по какому оборудованию нет данных.

### 4.6. Осмотры (этап 2)

Весенний и осенний осмотры общего имущества (Правила содержания общего имущества, ПП РФ № 491, п. 13), внеочередные после аварий и стихийных явлений, проверка готовности к отопительному периоду, приёмка дома в управление.

**Поля:** дом, тип, дата, комиссия, итог, акт осмотра (файл), фото, выявлено дефектов. Каждый дефект становится работой со ссылкой на осмотр. Так план текущего ремонта следующего года собирается из осмотров, а не с нуля.

**Стадии:** Запланирован → Проведён → Акт подписан (финал) / Отменён (финал).

### 4.7. Обращения, претензии и предписания — внешняя переписка по дому

Всё, что УК пишет по дому внешним организациям, и всё, что получает от них:

- **исходящие обращения через ГИС ЖКХ** в РСО (Ульяновскводоканал, Т+), в Управление ЖКХ администрации, в Агентство госжилнадзора — требования, претензии, заявления о несогласии с ответом. Источник — выгрузка обращений ГИС ЖКХ (шаблон `APPEALS_EXP`). **MVP**;
- **входящие предписания и проверки** — ГЖИ, прокуратура, Роспотребнадзор, МЧС, суд. Этап 2.

| Поле | Откуда (для ГИС ЖКХ) |
|---|---|
| Направление | исходящее обращение / входящее предписание |
| Дом | **GUID дома ГИС** — точное совпадение с ключом дома, без разбора адреса |
| Помещение | номер помещения (если указан) |
| Идентификатор ГИС ЖКХ, номер (`73-2026-36200`) | ключ источника |
| Родительское обращение | цепочка: требование → ответ → «не согласны с ответом» |
| Тема | код и название темы ГИС («5.1 Качество оказания коммунальных услуг») |
| Организация-получатель | компания CRM, найденная по ИНН (Водоканал — ИНН 7303005240) |
| Даты | создания, отправки, планового исполнения, фактического исполнения, просрочка в днях |
| Статус в ГИС и у получателя, наличие ответа | как в ГИС |
| Текст обращения | полный текст, HTML-разметка очищается |
| Ответы | каждый ответ — запись в ленте этого обращения: номер, дата, текст |
| Работы | что сделали по итогам (дочерние работы) |
| Для предписаний (этап 2) | орган, № и дата, суть, срок, возможный штраф, файл, отчёт об исполнении |

**Стадии:** Направлено / Получено → Ждём ответа → Ответ получен, контроль исполнения → Исполнено (финал) / Отозвано, обжаловано, отменено (финал).

**Контроль:**
- за 3 дня до плановой даты ответа без ответа — задача ответственному;
- если срок нарушен — пометка «просрочено» и задача на повторное обращение или жалобу в ГЖИ;
- 3 и более обращения по одному дому и одной теме за квартал — дом попадает в отчёт «хронические проблемы с РСО». В выгрузке от 07.10.2026 так выглядит б-р Западный, 1: 12 обращений в Водоканал, администрацию и ГЖИ.

**Ответ на вопрос «как отличить третью сторону»:**
- для обращений ГИС ЖКХ — по ИНН получателя;
- для заявок АСУ — по-прежнему нужен ваш ответ.

## 5. Как выглядит «вся история дома»

**Уровень 1 — стандартный Битрикс24, без доработок.**
- В карточке дома вкладки «Работы», «Заявки», «Оборудование», «Осмотры», «Предписания» — списки со всеми записями дома, с фильтрами и выгрузкой в Excel.
- Лента (таймлайн) дома. Программа пишет в неё ключевые события в хронологическом порядке, включая обращения в РСО и ответы на них: «12.03.2026 — авария: порыв ЦО, подвал, подъезд 2», «15.03.2026 — принята работа: замена участка трубопровода ЦО, акт № 45, 18 400 ₽, гарантия до 15.03.2027». Получается единая хронология дома.
- Битрикс сам ведёт историю изменений полей: кто, когда и что поменял.
- Задачи, привязанные к дому, видны в его карточке.

**Уровень 2 — вкладка «Паспорт дома» (этап 3).**

Своя вкладка в карточке дома, встраивается в Битрикс24 как приложение:
- шапка с ключевыми характеристиками и показателями;
- единая лента всех событий за все годы с фильтром по системе: «покажи всё по кровле» — осмотры, заявки о протечках, ремонты, гарантии;
- затраты по годам и по системам;
- повторяющиеся проблемы — дома и системы, где заявки идут снова и снова;
- кнопки «Паспорт дома (PDF)» и «Отчёт собственникам за год».

Технически вкладка работает в браузере сотрудника и берёт данные из Битрикса с его же правами. На нашем сервере данные клиента не хранятся. Для бизнеса это важно (раздел 9). Чтобы установить приложение, нужен администратор портала.

**Уровень 3 — документы.**
- **Отчёт собственникам за год по дому**: работы, суммы, акты, аварии. Это заготовка, которую юрист и бухгалтерия проверяют перед отправкой.
- **Паспорт дома для совета дома или для передачи дома другой УК.**

## 6. Справочники (общие для всех УК)

Справочники — то, что делает продукт тиражным: у всех клиентов одинаковые категории, поэтому отчёты и сравнения работают сразу.

**Конструктив и системы** (по составу минимального перечня работ, ПП РФ № 290): фундамент и подвал; стены и фасад (включая МПШ, балконы, отмостку); перекрытия; кровля и козырьки; лестницы и подъезды; окна, двери, входные группы; внутренняя отделка; мусоропровод; вентиляция и дымоудаление; ХВС; ГВС; отопление и ИТП; водоотведение и КНС; электроснабжение и освещение; газоснабжение; лифты; АППЗ и пожарная безопасность; приборы учёта; придомовая территория и благоустройство; санитарное содержание; слаботочные системы (домофон, видео, ТРЖ); прочее.

Категории из вашего годового плана («Благоустройство», «Кровля и козырьки», «Фасад и МПШ», «ТРЖ» и т. д.) сопоставляются с этим справочником один к одному или как часть раздела. Разметка, которую уже сделал `tools/extract_backlog.py`, не пропадёт.

**Остальные справочники:** виды работ, источники финансирования, типы оснований, органы надзора, третьи стороны, ключевые слова критичности. Всё в `config/`, клиент может дополнять.

## 9. Персональные данные и безопасность

- **Где данные.** Все данные лежат в Битрикс24 клиента. Программа хранит у себя только служебную базу соответствий (номер заявки → ID в Битриксе) и журналы без персональных данных.
- **Что не переносим.** ФИО и телефоны заявителей из АСУ по умолчанию не попадают в Битрикс, телефоны в тексте заявок маскируются. Председатели советов — это контакты, которые УК ведёт и сейчас.
- **Доступ.** Вебхук или приложение работают с правами конкретного сотрудника, ключ хранится вне кода.
- **Для продажи.** Пока мы не храним данные клиентов на своих серверах, нам не нужно становиться обработчиком их персональных данных по поручению. А это договоры, требования 152-ФЗ, серверы в РФ. Отсюда архитектурное решение: продукт работает у клиента (программа на его компьютере, вкладка в его Битриксе), а не как наш облачный сервис. Перед продажей нужна консультация юриста по 152-ФЗ.

## 10. Продукт для других УК

### Что продаём

«Паспорт МКД для Битрикс24» — готовое решение для УК и ТСЖ, у которых есть Битрикс24:

1. **Установщик схемы.** Создаёт в портале клиента смарт-процессы, поля, стадии, связи и справочники. Если у клиента уже есть похожие («Дома»), подключается к ним через `discover`, ничего не ломая.
2. **Загрузчики.** ГИС ЖКХ (дома и обращения — стандартные шаблоны, одинаковые во всех регионах), журнал заявок АСУ, годовые планы ремонта, ФКР. Первый формат АСУ — «Жилищный стандарт», остальные добавляются по мере появления клиентов.
3. **Автоматизация.** Задачи третьим сторонам, гарантийные случаи, повторные аварии, напоминания о сроках поверок, ТО, предписаний и осмотров.
4. **Вкладка «Паспорт дома»** и документы: отчёт собственникам и паспорт дома.
5. **Методика и обучение.** Как вести дом, кто и что отмечает, регламент приёмки работ. Шаблоны ролей и роботов Битрикса.

### Варианты поставки

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| А. Внедрение-проект | ставим и настраиваем у клиента, загружаем историю, обучаем | быстро начать, деньги с первого клиента, учимся на реальных УК | зависит от наших рук, плохо масштабируется |
| Б. Приложение в Маркете Битрикс24 | клиент ставит сам, подписка | масштабируется, Битрикс приводит клиентов | нужна регистрация разработчика, модерация, поддержка, своя площадка для работы приложения |
| В. Отдельный сервис вне Битрикса | для УК без Битрикса | шире рынок | это уже другой продукт, плюс 152-ФЗ на нашей стороне |

**Рекомендация:** вариант А на ваших трёх юрлицах, затем на 1–2 сторонних УК-пилотах. Вариант Б — когда схема и загрузчики стабилизируются на нескольких клиентах. Вариант В сейчас не нужен.

**Как брать деньги** (проверить на пилотах, цифры не придумываю): разовая плата за внедрение плюс абонентская плата за дом в месяц или за пакет домов (до 100, до 300, больше). Плата за дом понятна УК, потому что их доход тоже считается с дома и квадратного метра.

### Что подготовить к презентации

- **Демо-портал** Битрикс24 с вымышленными данными: 30–50 домов, история за 3 года, аварии, гарантийный случай. Реальные данные ваших УК другим показывать нельзя: это персональные данные и коммерческая тайна.
- **Сценарий показа на 10 минут:** «совет дома пришёл с претензией» → открываем дом → история кровли за 3 года → акты и фото → отчёт собственникам одной кнопкой → «а вот здесь повторная авария, и мы выставили претензию подрядчику по гарантии».
- **Цифры эффекта с ваших домов** после 2–3 месяцев работы: сколько времени уходит на отчёт по дому, сколько найдено гарантийных случаев, сколько заявок третьим сторонам взято на контроль.
- **Анализ конкурентов.** Специализированные системы для УК существуют. Наше отличие: работаем внутри Битрикс24, который у клиента уже есть, и не заменяем АСУ, а дополняем её. Могу отдельно собрать обзор.

### Риски

| Риск | Что делаем |
|---|---|
| Зависимость от Битрикс24: изменения API, тарифов, лимитов | используем только стандартные методы REST; схема описана в одном файле |
| У других УК другие АСУ и форматы выгрузок | загрузчики — сменные модули с общим форматом на выходе |
| Нет права на настройку CRM у пользователя | установщик сначала показывает, что нужно, и формирует письмо администратору |
| Данные «грязные»: адреса, дубли | нормализация адресов, список «на проверку», показатели качества данных в карточке |
| Сотрудники не отмечают работы | приёмка работ в Битриксе = единственный путь к оплате подрядчику (регламент); показатели по техникам |
| Тариф Битрикс24 ограничивает число смарт-процессов | проверить до внедрения; минимальная схема — 3 смарт-процесса (Дом, Работы, Заявки) |

|---|---|---|
| 0. Доступ | вебхук, `check`, `discover`, решения по разделу 12 | видим реальные поля «Домов» |
| 1. MVP «История дома» | `config/schema.yaml`; установщик схемы (Работы, Заявки, Обращения); импорт домов; импорт работ 2026 из годового плана и трекера; журнал АСУ; обращения ГИС ЖКХ с контролем сроков; лента событий дома; задачи третьим сторонам; отчёт | по любому дому видны работы 2026 года и заявки, без дублей при повторной загрузке |
| 2. Полный паспорт | оборудование (с заготовками из CSV), осмотры, входящие предписания; напоминания о сроках; гарантийные случаи и повторные аварии; показатели в карточке; история прошлых лет | карточка закрывает вопрос «что было с домом» без Excel |
| 3. Витрина | вкладка «Паспорт дома», отчёт собственникам, паспорт дома PDF, дашборды (BI-конструктор Битрикса) | отчёт по дому собирается за минуты |
| 4. Тиражирование | настройки для любой УК, демо-портал, документация внедрения, пилот у сторонней УК | установка у нового клиента за 1–2 дня без правки кода |

**Что меняется в уже начатом коде:**
- появляется `config/schema.yaml` — одно описание всех сущностей, полей, стадий и связей. По нему работают и установщик, и `discover`, и импорт;
- импорт пишется не только для домов, а как общий механизм «обновить или создать по ключу источника» для любой сущности. Ключ хранится в поле записи, а `state.db` — только ускоритель;
- новые команды: `schema` (что не хватает в портале и что будет создано, тоже с `--apply`), `import-works` (годовой план и трекер), `sync-gis-appeals` (обращения ГИС ЖКХ), `recalc` (показатели домов);
- порядок шагов прежний: доступ → `discover` → подтверждение полей → импорт домов → остальное.

## 12. Решения, которые нужны от вас

1. **Право на настройку CRM.** Есть ли оно у вас или у администратора, чтобы создать смарт-процессы «Работы», «Заявки» и «Обращения» и добавить поля? Без него MVP ограничится «Домами», задачами и лентой событий.
2. **Тариф Битрикс24.** Нужен, чтобы проверить лимит на смарт-процессы.
3. **Стадия «Аварийное состояние».** Вариант (а) или (б) из раздела 4.2.
4. **Заявки АСУ.** Загружать все или только значимые? Сколько заявок в месяц?
5. **История прошлых лет.** Какие файлы есть?
6. **Google-трекер.** Оставляем для подрядчиков или переводим всех в Битрикс?
7. **Выгрузка ГИС ЖКХ от 07.10.2026.** Я правильно понимаю, что это обращения, которые УК отправила через ГИС ЖКХ (в Водоканал, администрацию, ГЖИ)? В ней только два дома: это фильтр при выгрузке? Для истории нужна выгрузка по всем домам, хотя бы за 2026 год.
8. **Бизнес.** Кто будет владельцем продукта (юрлицо)? Есть ли знакомая УК для пилота?
